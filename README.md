# Modeling anticipatory and cue-driven responses in a gamified sustained-attention task for children

Analysis code for:

> Orsoni, M., RIccardi, A., Magri, S., Barbaresi, M., & Benassi, M. (2026). *Modeling
> anticipatory and cue-driven responses in a gamified sustained-attention task for children*.
> Zenodo. https://doi.org/10.5281/zenodo.24011594

In Eye-Riders A, an endless-runner game, children jump over or slide under obstacles after an auditory
cue, but the obstacle can be identified before the cue. Almost half of the responses come too early to be
based on the cue, yet they are as accurate as later ones. The repository contains every analysis of the
article: the checks of the drift diffusion model (DDM) assumptions, the behavioural regression models, the
Bayesian hierarchical mixture model in which each response is either timed to the visible obstacle or
generated by a diffusion process starting at the cue (Model 1), its comparison with two alternatives
(Model 2, fast-guess mixture; Model 3, two-stage mixture) and with a hierarchical truncated DDM,
parameter recovery and split-half reliability.

The analysis code, the container used for GPU estimation and the model outputs are archived on Zenodo:
[10.5281/zenodo.23590298](https://doi.org/10.5281/zenodo.23590298).

## Installation

**CPU environment** (Python 3.12 or 3.13), enough for everything except fitting the NumPyro models in
reasonable time:

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

**GPU environment** for the NumPyro models (Models 1-3, truncated DDM). The article used the Docker image
in `docker/` (Python 3.12, JAX 0.11.2 with CUDA 12.9, NumPyro 0.22) on an NVIDIA RTX 4060 laptop GPU
(Models 1-2, truncated DDM) and an RTX 5090 (Model 3):

```bash
docker build -t eyeriders-gpu docker
docker run --rm --gpus all -v "$(pwd)":/work -w /work eyeriders-gpu python code/06_fit_model1.py main
```

Notes:
- The models run in float32, as in the article (`MIX_X64=0`, the default). `MIX_X64=1` switches to float64
  (useful only for small CPU tests).
- On Windows, keep the repository in a folder whose path contains only ASCII characters: the netCDF
  libraries used to save posteriors fail on paths with accented letters.
- On CPU, the chains of the NumPyro models run in parallel on 4 virtual devices (set automatically).

## Data

The de-identified data are in `data/ER_A.xlsx` and are read from there by every script (another file can be
given with `EYERIDERS_DATA=/path/to/file.xlsx`). Their structure is described in
[data/README.md](data/README.md). Children are identified only by a code (`C001`-`C128`); the platform
identifiers and the dates of play have been removed (`tools/anonymize_data.py`). No other information on
the children (age, sex, school) is included.

## Running the analyses

Run every script from the repository root: `python code/<script>.py`. `run_all.sh` runs the whole pipeline.
Times are indicative (laptop CPU; NVIDIA RTX 4060 for the GPU steps).

| Step | Script | What it does | Article | Time |
|---|---|---|---|---|
| 1 | `01_descriptives.py` | counts, accuracy of early responses, share kept by a 150-ms cut-off | Method: Data; Results: *Early responses are informed*; Figures 1-2 | < 1 min |
| 2 | `02_ddm_assumption_check.py` | maximum-likelihood DDM per session, on all responses and on responses ≥ 150 ms; quantiles and skewness | *A standard DDM fits only the late responses* | ~20-40 min |
| 3 | `03_behavioral_models.py all` | Bambi models: omissions, action errors, early responses, timing (Student-t location-scale) | Method: *Behavioral models*; Table A1 | 5-10 min per model |
| 4 | `04_behavioral_contrasts.py` | contrasts for practice, minutes, levels; sequence effects | Tables 3, 4A, 5 (behavioural rows); Figure 5 | < 1 min |
| 5 | `05_early_responding.py` | individual differences in early responding | *Individual differences in early responding* | < 1 min |
| 6 | `06_fit_model1.py main` | fit of Model 1 **[GPU]** | Method: *Mixture model*, *Estimation* | ~15 min |
| 7 | `07_model1_results.py` | Model 1 estimates, contrasts, predictive simulation, P(timed) per response | Results: Model 1; Tables 3, 4A, 5 (Model 1 rows); Figure 3 | ~5 min |
| 8 | `08_fit_alternative_models.py model2` / `model3` / `ddm_trunc all` | fits of Model 2, Model 3 and the hierarchical truncated DDM **[GPU]** | *Alternative models*, *Estimation* | 12 min / many hours / 7 min |
| 9 | `09_model_comparison.py` | PSIS-LOO of Models 1-3; modes of Model 3 | *Model comparison*; Table 2 | ~10 min (~6 GB free RAM) |
| 10 | `10_loo_truncated.py` | truncated DDM vs Model 1 on responses ≥ 150 ms | *Model comparison* (last paragraph) | ~1 min |
| 11 | `11_posterior_predictive.py` | analytic predictive checks by condition | Results: Model 1 (predicted accuracy and quantiles); Figure 4 | ~5 min |
| 12 | `12_parameter_recovery.py simulate`, `06_fit_model1.py recovery`, `12_parameter_recovery.py evaluate` | parameter recovery of Model 1 **[GPU for the refit]** | *Parameter recovery and reliability*; Results: Model 1 | ~20 min |
| 13 | `06_fit_model1.py half0`/`half1`, `08_fit_alternative_models.py ddm_trunc half0`/`half1`, `13_reliability.py` | split-half reliability **[GPU for the fits]** | *Reliability*; Table 6 | ~45 min |
| 14 | `14_truncated_vs_model1.py` | contrasts of the truncated DDM vs Model 1 | Results RQ2-RQ4; Discussion (5 of 19 contrasts) | < 1 min |

Each fitting script has a `test` option (4 children, very short chains, not meant to converge; 1-15 min
on CPU) to check the installation, e.g.
`python code/06_fit_model1.py test` and `python code/08_fit_alternative_models.py test model2`.

### Reusing the saved model outputs

The fits are deposited on Zenodo. To reproduce the tables and figures without refitting, put the files in
`results/fits/` and run the non-fitting steps (01, 02, 04, 05, 07, 09-14).
The authors' original outputs (Italian file names) can be imported with
`python tools/import_saved_outputs.py <path to output_ipotesi> --raw <original export .xlsx>`; `--raw`
replaces the platform identifiers in the per-response csv files with the codes of `data/ER_A.xlsx`, and
must be used before the files are deposited.

The tables in `results/` and the figures in `figures/` of this repository were produced with this code from
the deposited model outputs; they reproduce the values reported in the article. Per-child outputs
(`results/ddm_check_*.csv`, `results/early_responding_by_session.csv`) are written locally and not
tracked.

| Hierarchical truncated DDM | `ddm_trunc` | `post_ddm_trunc_{all,half0,half1}.npz`, `ll_ddm_trunc_*.npy` |
| Behavioural models | `omissions`, `action_errors`, `early`, `timing` | `idata_behav_<outcome>.nc` |

Parameter names follow the equations in the header of `code/mixture.py`. The raw coding of the data is kept
in the variable names: `versione` = level (`breve` = Level 1, `lunga` = Level 2), `sessione` = session,
`cella` = level x minute cell (`B1`-`B4` = Level 1, minutes 1-4; `L1`-`L5` = Level 2, minutes 1-5),
`ver` and `sess` = -0.5 / +0.5 codes of level and session. In the contrast tables, RQ2 = practice,
RQ3 = time on task, RQ4 = levels, as in the article.

## Reproducibility notes

- **MCMC on GPU is not bit-for-bit reproducible across hardware and library versions.** Seeds are fixed
  (PRNG key 2026), but rerunning the fits gives draws that differ slightly from the deposited ones;
  summaries agree within Monte Carlo error. All tables and figures can be reproduced exactly from the
  deposited outputs.
- **Model 3 does not converge across chains.** Its posterior has three separate modes, in which the timed
  component and the early phase of the diffusion process exchange responses. `09_model_comparison.py`
  groups chains into modes and reports LOO for each chain and for the pooled chains of the best mode
  (one draw in 4, `MODE_THIN`); `11_posterior_predictive.py`
  uses the chains of the best mode. Starting values are dispersed across chains with `FIT_JITTER`
  (1.0 for Model 3, set in `08_fit_alternative_models.py`; 0 for the other models) and the population intercepts are separated from the mean of the child effects
  (`FIT_REPARAM=1`).
- Matrix products use full float32 precision (`jax_default_matmul_precision = "highest"`): the TF32 default
  of recent NVIDIA GPUs makes the gradient of the two-stage density inaccurate.
- On NVIDIA Blackwell GPUs (RTX 50xx), an XLA compiler error invalidated the initialisation of several
  chains; it was avoided with `XLA_FLAGS=--xla_backend_optimization_level=0`.
- Starting values for Models 2-3 and the truncated DDM (`inits/start_values.json`) are posterior medians of
  a preliminary fit of the mixture model; Model 1 starts from the prior medians.
